CLAVION — BharatCode API integration
====================================
Last verified: 2026-11-04. Status flags below say what was tested live vs. read from docs.

SOURCES
- Official API page: https://bharatcode.ai/build
- Live catalog:      GET https://bharatcode.ai/api/model/v1/models (public, no key needed)

ENDPOINT
- Base URL: https://bharatcode.ai/api/model/v1   (env: BHARATCODE_BASE_URL)
- Auth:     Authorization: Bearer <BHARATCODE_API_KEY>   (server-side only; never sent to the browser)
- Protocol: OpenAI-compatible. Clavion uses the official `openai` Python SDK with base_url set.
- Endpoints documented:
    POST /chat/completions   <- used by Clavion
    POST /responses          (stateless only: store:false; no previous_response_id, hosted tools,
                              background jobs, audio/video/file input -> 400)
    GET  /models

Default model: qwen-3.8-27b  (env: BHARATCODE_MODEL)

LIMITS (from docs)
- Students: 10M tokens/day. Lite/Pro: no daily allowance. Shared capacity; requests may queue.
- Output cap 32k tokens INCLUDING reasoning tokens -> always set max_tokens generously, or the
  visible answer can be empty.
- 503 = busy, retry after a few seconds. The SDK is configured with max_retries=3.

HOW CLAVION USES IT
- backend/app/llm.py         client factory, catalog lookup, ping
- GET /api/health/llm        catalog check; ?live=true also runs one tiny completion
- backend/scripts/check_bharatcode.py   capability probe (text, JSON, image, tools)
- Money arithmetic is never delegated to the model; it is done in Python.

ENVIRONMENT NOTE
Some networks intercept TLS; certifi then rejects bharatcode.ai. llm.py calls
truststore.inject_into_ssl() so Python uses the OS certificate store.
